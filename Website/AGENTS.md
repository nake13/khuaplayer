# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Khua website direction

- The product name on the site is “Khua Player” (wordmark, page title, meta, footer, closing headline, download buttons, labels) so it is not misread; body copy may use “Khua” as the short form after that.

- Source visual: `reference/final-design.png` (composition and particle language only; its ultra-condensed type was superseded).
- Keep the site self-contained under `Website/`; never copy app binaries into this folder or Git history.
- Use the real Khua icon from `public/assets/khua-icon.png`.
- Visual language: bone-white editorial canvas, monumental sentence-case type, electric cobalt/cyan particle velocity fields, and tiny vermilion registration accents. Avoid flat saturated color slabs, boxed number badges, and all-caps mono everywhere; those read cheap.
- Typography relies on fonts that ship with macOS (the audience is Mac users; other platforms get plain fallbacks): display is Helvetica Neue Bold with tight tracking, sentence case; exactly one accent word per headline is Bodoni 72 Book Italic (marked `*word*` in `src/content.js`); body copy is the system font (SF Pro Text via `-apple-system`; Iowan Old Style is the approved serif alternative if an editorial voice is wanted); navigation, buttons, eyebrows, and small labels use the system font (SF Pro via `-apple-system`), eyebrows as tracked uppercase; monospace (SF Mono via `ui-monospace`) appears only on diagram tech tags. Chinese uses PingFang SC for display, body, and UI, with the accent word in Songti SC Black. No web-font packages are loaded.
- Buttons and controls are pill-shaped and sentence case. The header is fixed with a frosted-glass background and flips to a dark glass automatically over dark or blue sections.
- The performance diagram is a single Apple-style isometric stack showing the path a frame takes: the file as a flat card, Khua Player, Metal · VideoToolbox, a glowing zero-copy band, Apple silicon. No comparison with “other players” (unverifiable, and a competitor comparison by implication). Labels stay one or two words; the caption carries the explanation and keeps “Wherever the format allows”, because unsupported formats use the FFmpeg/dav1d software path.
- Match all 17 languages in the app's `Localizable.xcstrings` catalog. Use a native language picker on both the homepage and release history showing only the 17 actual languages, with the currently displayed language selected. The user explicitly rejected an Automatic option for the website: language detection is background behavior, not an exposed setting. Resolve language from an explicit `?lang=`, then a saved manual choice, then supported browser languages, then a conservative Cloudflare country hint, then English. Never let IP override any matching browser language or explicit choice. Accept legacy `zh` links as `zh-Hans` and distinguish `zh-Hant`. Only manual picker actions may save preferences; shared links are visit-only, and inferred languages must not be saved or inserted into the URL. Automatically detected visits keep clean URLs; manual/shared-language links retain their language. Ignore the old mixed-purpose `khua-site-locale` key. Copy lives in `src/locales/<locale>.json`; keep all versions natural rather than mechanically literal. Run `npm run test:i18n` to verify complete copy, placeholders, app-language parity, release-note coverage, preference changes and async races.
- Only query `/api/locale` when no browser language matches. Read the trusted `request.cf.country` at the edge and return a supported locale or null, not IP/location details. No third-party geolocation, cookies, database writes, visitor logs or shared response caching. Limit the optional lookup to one second; offline, timeout and uncertain/multilingual regions keep English. Cancel late results after manual selection, navigation or browser-language changes.
- Keep language-specific font stacks local to the OS. Fit the hero to the widest rotating word without layout shifts, verify 320–1920px layouts, and keep the language picker keyboard-accessible. Privacy/license documents remain authoritative English downloads, labeled as such; do not silently substitute a translated legal document.
- Release-note translations are website presentation only. Never alter signed Sparkle feeds, download artifacts or the R2 catalog for a copy-only change. New or changed remote release notes fall back to explicitly labeled English until their website translations are added and verified against the source notes.
- Primary positioning: “A media player built for speed.” / “为速度而生的多媒体播放器。” (page title and hero).
- Chinese copy is written as Chinese, not translated from the English: short, spoken rhythm (双击就播、边下边播、照样能播), no translationese such as “为你 Mac 里的那颗芯片而写”, “亲自上色”, “关掉即静”. Each section may make a different point from its English twin when that reads better; facts must match.
- Hero rotating word: the hero headline accent is written as `*{}*` in `src/content.js` and filled from `hero.rotating`. Index 0 is canonical (page title, `aria-label`, and what shows when motion is off) and must stay `speed` / `速度`. The shipping set is `["speed", "responsiveness", "fluidity", "efficiency", "performance"]` and `["速度", "迅捷", "流畅", "效率", "性能"]`: one performance facet per word, all nouns in English because "built for" takes a noun (`efficient` is invalid, `efficiency` is the noun). The design is tuned to the words, not the other way round: the hero icon sits at the bottom-right of `.hero-copy` (never in the headline band) and the headline is `9.6vw` capped at `9.6rem` so `responsiveness`, the longest word, clears the copy edge at every width from 320 to 1920 with a margin of at least 9px. If a longer word is added, re-run the width check (`period right <= .hero-copy right`, no intersection with `.hero-art`, constant `h1` height across words) before trusting a screenshot. Chinese entries fill 为X而生 and should stay two characters so the line never shifts. Below 760px the run before the slot is forced onto its own line so a longer word cannot change the headline height mid-rotation.
- Apple feature names follow Apple’s own terms: “Quick Look” in English, “快速查看” in Chinese (not “预览”, which is the Preview app).
- Copy should let a non-technical reader understand the product's edge: opens instantly with a short file-to-screen pipeline (VideoToolbox, Metal, zero copy), resilient playback of damaged and still-downloading files, on-device subtitle generation and translation, the Particle Star Trail timeline, plays the files people already have (MKV, HDR, 4K, VVC, ProRes, MXF; existing subtitle files next to the video load automatically), Quick Look previews for MKV, light by design, private by default, open source, plus everyday details (resume, hold-Space Turbo, Brightness Boost, multichannel audio, default player, volume boost, multiple windows, 17 languages).
- Section order: hero, Performance, Resilient playback, Boosts, Formats, On-device subtitles, Quick Look, Particle Star Trail, Light by design, Privacy, Open source, Details, closing. Backgrounds alternate dark / light so no two dark sections touch. The nav lists every section except Light by design; nine English labels need about 1400px (with the “Khua Player” wordmark), so below that the English nav hides while the shorter Chinese nav stays until 1100px.
- Boosts (`增强功能`) shows before/after demos in `src/BoostDemos.jsx`, all using the site's shared “kyoto-by-night” footage (`src/KyotoScene.jsx`). Motion+: 2× frame interpolation via Apple's system frame-rate conversion; requires macOS 26 and a supported Mac, videos up to 4K, 1× speed only, coverage may be partial on a busy Mac; hold C while it is on for the app's side-by-side compare, whose labels (Original / 2× Interpolation, 原始 / 插帧 2×) the demo reuses. The demo renders the same pan at 24 and 48 fps; both halves must differ only in frame rate. Brightness+: SDR video uses the display's extra EDR headroom; HDR does not need it; a web page cannot show that brightness, so the demo is labeled an illustration. Turbo: hold Space for 2×, configurable up to 5×, pitch preserved; the demo's HUD copies the app's amber chevrons (#ffb65c). The app's chips read “Motion+” / “Brightness+”; menus and tooltips still say “Motion Boost” / “Brightness Boost”.
- Resilient playback is `坏文件也能播` in Chinese (nav and eyebrow; `韧性播放` was rejected as hard to understand), headline 没下完、有损坏，照样能播. Claims must stay best-effort: Khua plays what can be played, repairs container damage in a read-only in-memory overlay (never modifies the file), steps past what it cannot recover, marks damaged spans on the timeline, starts a still-downloading or still-recording file as soon as it can and continues as data arrives, and explains failures. Never promise that every broken file plays. Timeline damage classes use the app's own words: Partial / 勉强可播 (amber), Unavailable / 没有内容 (red), not downloaded yet / 尚未下载 (gray); the app's notice is “Waiting for download…” / “等待下载…”.
- Subtitle generation and translation use Apple's on-device speech and translation frameworks and require macOS 26; say so wherever the feature is described, along with the fact that macOS may download a language model the first time. The translation appears above the original line (bilingual), existing text subtitles can be translated too, cues appear as they are generated, and the result is saved as SRT next to the video.
- The Particle Star Trail demo (`src/StarTrail.jsx`) is a Canvas port of `Apps/Mac/UI/SPDustLayer.swift`; keep its tuning in sync with the app when the app changes. Facts it illustrates: default timeline style; colors sampled from the video; density from bitrate; watched part settles into a line, the rest drifts; pointer glow (brighter than white only on XDR displays, which the web cannot show); Liquid and Classic are the other styles. The same engine draws the resilient-playback card in film colors too (a cool night palette, so amber and red can only mean damage), because in the app damage tints sit on top of the video's colors in every timeline style and healthy files show no tint at all. Its legend lists only what the app names or draws: 勉强可播 / Partial and 没有内容 / Unavailable (the app's hover labels), plus a sentence for the gray, sparse not-yet-downloaded span, which the app draws but does not label. Never add a "plays normally" swatch: normal spans are the video's own colors. The demo uses the tint color outright instead of the app's 55% / 65% mix, since that mix turns blue scenes beige on a static page.
- Do not describe the app as free or make promises about pricing; a paid tier is possible later while the core stays open source. Emphasize open source, not price.
- The source repository is public at `https://github.com/nake13/khuaplayer`. Keep GitHub source and issue links visible in normal builds, use shared destinations from `src/repository.js`, and describe the code as available now in every language, not as a future release.
- Do not mention competitors, size comparisons, excluded experimental features (super resolution), pricing, benchmarks, or unverified speed numbers. Motion+ frame interpolation ships in every public channel since 0.5.0 and is a headline feature.
- Subtitles: Khua loads embedded subtitles and subtitle files already sitting next to the video. It never searches for or downloads subtitles; copy must not imply that it does (avoid "finds subtitles for you" / "字幕自动找到"). Generated subtitles are made on the Mac from the video's audio, not fetched; only the macOS language model may be downloaded, by the system.
- Motion should be abundant but respect `prefers-reduced-motion` and remain usable on smaller screens. Motion layers: particle canvases — one field for the whole page, every section has one, each a local shape tied to its meaning (hero streams out of the app icon, Performance bursts from the chip, demo sections carry a sparse ambient drift, Formats runs parallel strands, Light by design converges to a point, Privacy is held in a circle, Open source releases outward, the close is a vortex); no pre-drawn dashed motifs and no shape used twice (three depth layers with their own speed and scroll/pointer parallax, fade-in/out over each particle's life, speed-linked brightness, tapered tails and soft round sprite heads; dark sections draw additively with a brighter ramp); scroll parallax through `data-parallax` (a fraction of scroll speed written to `--py`; positive values lag behind the page); pointer tilt on the hero icon (fine pointers only); staggered headline-line and format-token reveals; a fixed film-grain overlay at ~5% opacity; the two timeline demos (autoplaying playhead, simulated download, occasional phantom pointer sweep) and the subtitle cue cycle. All of it switches off under reduced motion or the header pause button; the timelines then hold a still frame (pausing mid-play freezes in place) but still respond to hover and drag, and stop drawing once they settle.
